**Root Cause**: TypeScript's `exactOptionalPropertyTypes: true` distinguishes between:
- `field?: Type` - property can be absent or Type
- `field?: Type | undefined` - property can be absent, undefined, or Type

When passing objects with potentially undefined values, we need the second form.

## Patterns Established

### Pattern 1: Conditional Spread for Optional Properties

**Use When**: Passing optional properties to functions/constructors with `exactOptionalPropertyTypes: true`

```typescript
// ✅ CORRECT
const result = await handler.execute({
  requiredField: value,
  ...(optionalField !== undefined && { optionalField }),
})

// ❌ WRONG (causes TS2379)
const result = await handler.execute({
  requiredField: value,
  optionalField: maybeUndefined, // Type error!
})
```

### Pattern 2: DTO Type Definitions

**Use When**: Defining DTOs/Input types for commands and queries

```typescript
// ✅ CORRECT
export type MyDto = {
  required: string
  optional?: Type | undefined  // Explicit undefined!
  nullable?: Type | null | undefined
}

// ❌ WRONG (incompatible with exactOptionalPropertyTypes)
export type MyDto = {
  required: string
  optional?: Type  // Missing undefined!
}
```

### Pattern 3: Nullable Field Filtering

**Use When**: Optional fields can be explicitly `null`

```typescript
// ✅ CORRECT
...(value !== undefined && value !== null && { field: value })

// ❌ WRONG (allows null to pass through)
...(value !== undefined && { field: value })
```

## Known Issues & Gotchas

1. **Parent Directory Pollution**: The working directory `E:\Projects\Camp-OS-refactor\` contains other project folders that TypeScript was trying to check. This is now fixed in `tsconfig.json`, but be aware if adding new include paths.

2. **exactOptionalPropertyTypes Strictness**: This is one of the strictest TypeScript flags. All optional properties MUST explicitly include `| undefined` in their type definition, not just the `?` operator.

3. **DTO Pattern Consistency**: All Command/Query DTOs should follow the same pattern for consistency. Any new DTOs should use `field?: Type | undefined` for optional fields.

4. **Test Mocks Falling Behind**: Integration tests use manual mocks that can fall out of sync with interfaces. Consider using a mock generator or ensuring CI fails when mocks are incomplete.
